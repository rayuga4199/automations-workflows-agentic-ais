# Research — Neighbourhood Tool Library

## What the evidence says

**Existing platforms:** The Tool Library in Portland, Oregon uses [MyTurn](https://myturn.com/lending-libraries/), a platform designed specifically for tool lending. [Lend Engine](https://www.lend-engine.com/features/self-serve-lending-library-platform) is another platform offering member-facing browsing and reservations with simplified volunteer workflows — staff and volunteers only need to process checkouts when members arrive, not manage transactions online. Both separate the catalogue and reservation system from the main website, which serves as an informational hub.

**Reservation handling:** The Tool Library's FAQ shows a practical model: items held for "TWO Tool Library business days" before moving to next in queue. High-demand tools use a waitlist system; the most expensive specialist tools require advance reservation with a $20 fee to manage demand and reduce no-shows.

**Small catalogue advantage:** The Library of Things Toolkit notes that "small LoTs benefit from using LoT-specific software rather than spreadsheets alone," but emphasises that software should track "who is borrowing and returning what" as the core function. The toolkit warns against over-investment in features and recommends examining user experience for both members and volunteers — a signal that vendor lock-in risks are real for small operations.

**Back-end friction:** Airtable templates combined with Google Forms can automate data entry. However, "volunteers sometimes struggle with remembering processes they don't use frequently" — suggesting automation and simplicity matter more than feature richness in the back-end.

**Usability for browsing:** Filter UI best practices recommend combining search (for known items) with filters (for exploratory discovery), using plain language labels, limiting visible filters to high-use criteria, and showing result counts. For a small catalogue, horizontally scrollable filter chips work better than full panels.

## What changed recently

The trend is away from bespoke systems. Lend Engine's positioning emphasises running your "whole library website" rather than integrating separate tools, suggesting consolidation pressure on platforms. Tool library peer-learning infrastructure has formalised — new libraries now have structured support networks.

## What we do not know

**Catalogue rot mechanisms:** The brief names catalogue rot as a key risk, but the evidence does not explain what triggers it. No source describes how often items are marked unavailable or what volunteer workflows fail most often.

**Reservation confidence:** None of the sources measure borrower hesitation or conditions under which borrowers trust a reservation will be kept.

**Volunteer sustainability:** Sources mention platforms simplify staff work, but offer no data on training time, error rates, or staff satisfaction in real deployments.

**Low-code back-end costs:** No evidence comparing the real time and error cost of managing a 150-item catalogue via Airtable against purpose-built tools like MyTurn or Lend Engine.

## Primary research plan

**Recruit:** 3 active volunteers from tool libraries within 50 miles (focus on people who update inventory at least monthly). 1 volunteer coordinator if available.

**Method:** Semi-structured interviews focused on past behaviour around catalogue maintenance, not hypothetical features.

**Interview questions:**

1. Walk me through the last time you updated the tool library's catalogue — which items changed, how did you make those changes, and what took the most time?
2. How often do you hear from borrowers frustrated because an item wasn't available or wasn't there when they came to collect it?
3. What information do you need about each tool to feel confident updating the system? How do you get that information now?
4. Tell me about the last time a reservation went wrong — what happened, and what should have been different?
5. If you could change one thing about the way you manage the catalogue right now, what would it be and why?
